# C5 handoff

## Done

- **`services/apps/quote-service`** serves the six `/v1` endpoints of spec 5.3. It uses the C0 zod
  schemas unchanged, and every response is parsed by its schema before it leaves the process.
  - `GET /v1/availability`, `POST /v1/offers`, `POST /v1/offers/{id}/prepare`,
    `GET /v1/bookings/{id}` and `POST /v1/bookings/{id}/cancel-preview` (guest JWT),
    `GET /v1/yield/terms`, and `/v1/openapi.json`.
  - **Policy materialisation** (`src/property.ts`) turns local rules into UTC cutoffs in the
    property's IANA zone. It applies explicit DST gap and overlap rules (ADR 0012 §1) and runs the
    same stay guards as `deposit`.
  - **Holds** (`src/db.ts`, `migrations/`): a Postgres exclusion constraint allows one active hold
    per overlapping slot. A per-resource advisory lock prevents exclusion-check deadlocks. Holds
    last 25 minutes. Once a quote is issued, the hold awaits payment and ends only on proof: the
    indexer hands it over, or the safe head proves the quote unpaid (ADR 0012 §2, §3, as amended by
    review 0003).
  - **Prepare:**
    - Reads live terms at one pinned block: fee, split, `pendingFeeAt`, pause, `lossDebt`, cap and
      signer.
    - Caps expiry before a pending fee change and 409s inside the last minute.
    - Fails closed on stale feeds (900 s), calendar overlaps, pause, loss debt, the cap, signer
      mismatch and clock skew (ADR 0012 §4, §5).
    - Allows one live quote per offer; re-preparing with the same guest is idempotent.
    - Refuses a replacement quote if an earlier one was deposited.
    - `calls` = USDC `approve(escrow, price)`, then `deposit(quote, sig)`: real addresses and
      calldata, no `stub` flag.
  - **Signer** (`src/signer.ts`):
    - AWS KMS secp256k1 is the default, with DER to (r, s, v), low-s and address recovery checked.
    - The local key signer is Anvil-only.
    - At boot the service checks the RPC chain id, the escrow's ERC-5267 EIP-712 domain and
      `quoteSigner`.
  - **Guest auth** (`src/auth.ts`):
    - ES256/EdDSA JWT with `iss`, `aud`, `exp` and `iat`, at most 1 hour old.
    - Exactly one of `addr` or `email`.
    - An unknown booking and someone else's booking both return 403.
  - **Read model:** interim, direct from chain (`src/readModel.ts`), behind `BookingReadModel`
    until C6 replaces it.
  - **Yield estimate:** the spec 8 formula (deployment window = check-in − 14 days − now, 90%
    deployable, rounded down), with the configured APY. It is labelled an estimate, with `asOf`.
- **`services/packages/abi`** is generated from `contracts/abi/*.json`. Its `test` fails if the
  output is stale.
- **`services/packages/shared`:**
  - `settlement.ts` is the TS reference evaluator: `refundBpsAt`, `refundOf` (ceil),
    `settlementFigures`, `bookingYield`, `validCurve`.
  - `eip712.ts` holds the typed data and `bookingIdOf`. It matches the Solidity test vector.
  - `api/openapi.ts` holds the OpenAPI builder, moved from api-stub, which now wraps it with its
    scenario header.
- **`contracts/script/DeployLocal.s.sol`** is an Anvil-only deployment for integration tests. It
  writes `contracts/deployments/local.json` (gitignored).
- **ADR 0012**, `.env.example`.

The brief's four tests:

1. **Differential** (`test/anvil/anvil.test.ts`): random quotes on the real contract. The inputs
   are the fee (changed through the timelock), the split, a 1–4 point curve, `finalBps`, nights,
   price, donated yield, and either a cancel at a random time or a settle after grace. The refund
   bps, refund, owner principal, fee, `y` (checked against the accumulator), guest yield and owner
   yield match the TS evaluator exactly.
   - **Mutation check:** with `refundOf` changed to round down, the suite fails. It shrinks to a
     100.000001 USDC booking at 1 bps.
2. **DST** (`test/materialise.test.ts`): Europe/Athens spring-forward and fall-back days, the gap
   and the overlap.
3. **Fee straddle** (`test/anvil`): with a proposed fee change:
   - the quote expires at `pendingFeeAt - 60`;
   - inside the last minute prepare returns 409 `terms_changed`;
   - after the change, the service's quote reverts with `QuoteExpired`;
   - an uncapped pre-change quote reverts with `FeeMismatch`;
   - the next quote carries the new fee.
4. **Signature** (`test/anvil`):
   - a service-signed quote deposits;
   - nine tampered fields each revert with `InvalidQuoteSignature`, as do another key and another
     chain id;
   - `hashQuote` equals the TS `bookingIdOf`.

**Acceptance:**

- **E2E on Anvil:** offer, prepare, then the `calls` executed by a smart wallet (`BatchWallet`,
  triggered by a third party). The booking exists with the quoted terms, cutoffs and 15:00/11:00
  EEST instants.
- **Concurrency:**
  - 50 concurrent offers for one slot produce one hold;
  - overlapping concurrent offers: over 10 rounds, the winners are pairwise disjoint and every
    loser gets `SlotTaken`;
  - 8 concurrent prepares produce one quote.
- **`feeBps`** appears only inside `quote`. The offers test asserts its absence.
- **Process smoke test:** the built `dist/server.js` against Anvil, driven with curl, did
  availability, offer, prepare, `approve` + `deposit` from an EOA (both `success`), booking read
  with a JWT, and cancel-preview.

### Running on Anvil

```
anvil &                                                   # or: anvil --timestamp $(date +%s)
cd contracts && forge script script/DeployLocal.s.sol --rpc-url http://127.0.0.1:8545 --broadcast
cd services && pnpm -r build
cd apps/quote-service && cp .env.example .env             # then set:
#   ESCROW=<escrow from contracts/deployments/local.json>  CHAIN_ID=31337
#   SIGNER=local  LOCAL_SIGNER_PK=<anvil account 2 key, see DeployLocal.s.sol>
#   JWT_PUBLIC_KEY_PEM=<your test key>  PROPERTIES_FILE=<json array, src/property.ts>
node --env-file=.env dist/server.js
```

Anvil's clock must be close to wall time (`MAX_CLOCK_SKEW_SEC`, 120 s). Otherwise prepare refuses
to sign, by design.

### Running against Base Sepolia

1. Deploy with the owner's wallet: `DeployBaseSepolia.s.sol`, see its header. Then onboard the
   property owner with `approveOwner` and `createEscrow(owner, <KMS key address>, minNightly)`.
2. Create an AWS KMS key with spec `ECC_SECG_P256K1` and usage `SIGN_VERIFY`. Grant the service's
   IAM role `kms:Sign` and `kms:GetPublicKey`. Its address is logged at boot.
3. `.env`:
   - `RPC_URL=https://sepolia.base.org` (or a keyed RPC from the environment, never committed);
   - `CHAIN_ID=84532`, `ESCROW=<clone>`, `ESCROW_FROM_BLOCK=<clone creation block>`;
   - `SIGNER=kms`, `KMS_KEY_ID`, `AWS_REGION`;
   - the JWT issuer, audience and key from the checkout backend.
4. Boot fails if the chain id, the EIP-712 domain or `quoteSigner` does not match.

## Deviations from spec

- None to the contract or the `/v1` schemas.
- **Documentation only:** the OpenAPI document now lists 409 `unavailable` on `POST /v1/offers`.
  The error code already existed in the C0 schema. See ADR 0012 §2.

## Spec concerns

- Spec 5.3 does not say what `POST /v1/offers` returns when the slot is held. I chose 409
  `unavailable`; the agent workstream should confirm it.
- The contract has no overlap check (by design, spec 4.2/9). Since review 0003, a quoted hold is
  released only on proof, so double-booking safety no longer depends on how fast C6 indexes. C6 must
  still write escrow bookings into `calendar_blocks` with `source = 'escrow'` and `ref = bookingId`.
  That row is how a hold hands over.
- **Test correction** (CLAUDE.md §6: I say so here): my own earlier holds test asserted "at most
  one wins" for four concurrent ranges. Two of those ranges are disjoint, so two winners is
  correct, and the test was order-dependent. I replaced it with the right property: winners are
  pairwise disjoint and losers get `SlotTaken`. The stronger test then exposed the 40P01 deadlock,
  which is now fixed.

## Update: read model moved to the indexer (after C6)

- **`src/readModel.ts` has a new `indexerReadModel(INDEXER_URL, escrow)`.** It reads the C6 read API
  (`/v1/indexer/bookings/:escrow/:bookingId`, docs/adr/0017 §8) behind the same
  `BookingReadModel` interface:
  - every response is validated with zod: decimal-string money, v1 enums, checksummed addresses;
  - a 404 is an unknown booking, which the API answers with 403 as before;
  - any other status, or a mismatched booking id, is an error, never a guess;
  - requests time out after 2 s.
- **`server.ts` uses it when `INDEXER_URL` is set.** Without it, the chain read model stays as the
  fallback. `.env.example` sets it.
- **The `/v1` API is unchanged.**
- **Tests:**
  - `test/readModel.test.ts` (4) covers mapping, 404, malformed money, unknown states, a mismatched
    id and server errors. `pnpm test`: 77 passed.
  - An integration check in the C6 acceptance run
    (`services/apps/indexer/test/anvil/acceptance.test.ts`): for all 65 bookings, the indexer model
    and the chain model return identical `BookingView`s.
  - The first run found one difference, address casing (Ponder stores lowercase), now normalised.
