# C3 handoff

## Done

- `openDispute`, `resolve` and `resolveByDefault`, with partial settlement at open, yield
  crystallised at open, and the D3 yield rule at resolution (spec 7, ADR 0011).
- The guest opens (D8). The booking must be DELIVERED and not frozen, before `checkOut + GRACE`,
  with `0 < contested <= principal`.
- Only the arbitrator snapshotted on the booking can resolve. There is no recipient parameter
  anywhere.
- `resolveByDefault` is permissionless from `disputeDeadline`, which frozen time extends
  (ADR 0011 §3).
- During `lossDebt`, yield is deferred and the guest's principal refund is paid.
- **`reasonCode` enum `DisputeReason`:**

  | Code | Reason |
  |---|---|
  | 0 | NOT_AS_DESCRIBED |
  | 1 | ACCESS_OR_CHECK_IN_FAILURE |
  | 2 | CLEANLINESS_OR_MAINTENANCE |
  | 3 | SAFETY_OR_HEALTH |
  | 4 | AMENITY_MISSING |
  | 5 | BILLING_ERROR |
  | 6 | OTHER |
  | 7 | DEFAULT_TIMEOUT (reserved for `resolveByDefault`) |

- Views: `getDispute(bookingId)`, `disputeDeadline(bookingId)`, which returns 0 if the booking was
  never disputed.
- Linked `DisputeLib` over the shared `Ledger` (ADR 0010 pattern). Escrow is 20,732 B, with 3,844 B
  of headroom.
- The C2 invariant handler now opens and resolves disputes (by the arbitrator and by default)
  inside random gain, loss and debt sequences.
- ABIs re-exported; the deploy script note updated (four libraries, ~11.5M gas simulated).

## Not done

  bookings (D9: none).
- C9 can now start (wave 2b): the dispute ABI is published.

**Written tests first** (implementation after). Validated two ways:

- **Planted bugs,** introduced one at a time and each caught:
  - no arbitrator check: blast radius, guards and snapshot tests
  - frozen time ignored in the deadline: freeze test
  - yield not crystallised at open: books identity (unit and invariant) and INV-4
  - guest yield vests on a guest win: D3 unit and invariant checks
  - refund rounded down: rounding unit test and the invariant's spec-formula check
- **Invariant handler checked under `fail_on_revert=true`** across 6 seeds, with disputes occurring
  in every sampled run. Two handler bugs were found and fixed along the way: a random pick missed
  most eligible bookings, and a seed-plus-offset overflow. Neither was a contract bug.

**Slither:** 31 results, no new categories beyond C2's triage; two more `timestamp` findings (the
dispute window). The coverage build needed two test functions restructured (stack depth under the
unoptimised compile); the contracts were unaffected.

## Deviations from spec

1. Frozen time extends `DISPUTE_WINDOW` (ADR 0011 §3). The brief left this to C3; I chose against
   its recommendation, for the reason in the ADR.
2. `DisputeOpened` carries the uncontested figures and `y` (ADR 0011 §4).

## Spec concerns

- **GRACE can lapse during a freeze.** Spec 3.5 says frozen time does not extend `GRACE`. A guardian
  can therefore freeze a delivered booking across `checkOut + GRACE`, and the guest loses the chance
  to open a dispute. The same reasoning as ADR 0011 §3 suggests extending `GRACE` by frozen time
  too. Not changed, because it is spec text (C1's domain); the project owner decides.
- **The arbitrator is one party for the pilot.** Spec 7's note stands: before mainnet the arbitrator
  Safe needs a majority of signers independent of the platform and the owner.
- `reasonCode` is fixed at deployment; new reasons need a new implementation.
