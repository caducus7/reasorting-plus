# C7 handoff

**ADR:** [0018](../adr/0018-ical-channel-sync.md). **Runbook:** `ops/runbook.md` → Channel sync
(this includes how the owner adds a channel).

## Done

- **`services/apps/ical-sync`**, one service. It imports channel feeds into `calendar_blocks` and
  serves our export feeds. It uses ical.js for both directions, `undici` plus `ipaddr.js` for safe
  fetching, and C6's `inv3`, alert outbox and `localStay`.
- **Import** (`src/importer.ts`, `src/parse.ts`):
  - per-feed conditional GET every 5 minutes;
  - RFC 5545 parsing: all-day events, TZID with or without VTIMEZONE, UTC, floating times,
    RRULE/EXDATE/RECURRENCE-ID, cancelled events and missing DTEND;
  - normalisation to property-local nights with an exclusive end;
  - upsert by (feed, UID) and deletion of events that left the feed, in one transaction;
  - failures back off (5 → 60 min) and never delete.
- **Staleness:**
  - `channel_feeds.last_success_at`, which C5 already fails closed on;
  - configured feeds start as never imported;
  - a `FEED_STALE` alert.
- **Conflicts:**
  - INV-3 through C6's notifier, with both references;
  - one alert per conflict;
  - a timestamped log in `ical_sync.conflicts`;
  - auto-resolved when the overlap clears.
- **Export** (`src/export.ts`, `src/sources.ts`):
  - `GET /ical/<token>.ics`, one feed per resource and channel;
  - contains bookings whose deposit reached `safe`, removed on cancellation once that is at `safe`;
  - "Reserved" only, with an HMAC UID, so nothing links to the guest or the on-chain booking;
  - ETag and 304s.
- **Untrusted input** (`src/fetch.ts`):
  - https only;
  - public-unicast addresses only, checked at connect time (DNS-rebinding safe);
  - at most 3 redirects, each re-checked;
  - a 15 s timeout, a 5 MiB cap and a 5,000-event cap.

### Feed URL format

- **Export (ours, given to channels):**
  `${PUBLIC_BASE_URL}/ical/${base64url(HMAC-SHA256(EXPORT_TOKEN_SECRET, "ical-export:v1:<resourceId>:<channel>"))}.ics`.
  The service prints each one at start. They are secrets for the channels; rotate them via the
  secret.
- **Import (the channels', configured by the owner):** the channel's own export URL, in
  `FEEDS_FILE` (secret, gitignored; see `feeds.example.json`).

## Not done

- **Milestone I3.** It needs the owner's real listing on a channel: a round trip, plus a forced
  conflict alerting. See "Blocked".
- **The iCal-export half of INV-3 in C6's monitor.** The export is derived on each request from the

## Deviations from spec

- **The export UID is an HMAC of the bookingId, not the bookingId.** The bookingId is public
  on-chain and would link a channel's calendar to the guest's wallet.
- **Cancellations leave the export at `safe`, not at once.** This matches ADR 0017 §2, so a
  reorged-away cancellation cannot free a slot on a channel.

## Spec concerns

- **A channel glitch can mass-delete blocks.** Following the brief, a feed that returns a *valid*
  but empty calendar deletes all of that feed's blocks, and C5 could then sell those dates. A common
  guard is to hold a removal of more than half of a feed's future blocks until two consecutive
  polls confirm it. I did not add it (it is not in the brief), but I recommend it.
- **Residual race (spec 9).** A channel polls our export on its own schedule, so a room can be sold
  there between our deposit reaching `safe` and the channel's next poll. The conflict alert and
  runbook cover it; a channel manager API closes it (post-MVP).
- **The fixtures are format-faithful, not real exports.** A real export shows an address and the
  dates nobody is home, and the public "samples" I found are synthetic and unlicensed. The
  real-data check is milestone I3.

## Interfaces changed

- **No `/v1` schema, contract interface or shared table DDL changed.**
- **C6 `AlertOutbox`:** added `open()` and `resolve(keys)`. Additive; indexer suites pass.
- **`@chain/indexer` package `exports`:** added `./alerts`, `./invariants`, `./calendar`,
  `./projection` and `./ops`, and the build now emits declarations.
- **New tables:** `ical_sync.feed_state` and `ical_sync.conflicts` (C7-owned).
- **C7 now writes `channel_feeds` and the channel rows of `calendar_blocks`.** These were already
  C7's per ADR 0012.

## Blocked

- **Milestone I3.** It needs the owner's real listing on one channel (Airbnb or Booking.com): the
  export URL imported by the channel, the channel's feed in `FEEDS_FILE`, a round trip, then a forced
  overlap to see the alert.
