## Done

- **D5 spike on the fork** (`test/fork/AaveSpike.t.sol`, with a spike-only thin adapter in
  `test/fork/spike/`). Both options were measured on code size, rounding, fees, full utilisation,
  donation exposure and pause behaviour.
  - Decision: Aave's **StataTokenV2**, used directly as the escrow's ERC-4626 vault. There is no

  - The addresses come from `bgd-labs/aave-address-book@f9858202` (`AaveV3Base.sol`) and are
    asserted on-chain.
- **Finding:** the stata token's pause is an EIP-4626 deviation. `maxWithdraw` stays above 0 while
  `withdraw` reverts. The fix:
  - `LedgerLib.claim` now pulls **best effort**: try/catch around both `maxWithdraw` and `withdraw`,
    with the balance delta measured.
  - MetaMorpho is the precedent (ADR 0016).
  - A pause at Aave no longer blocks guest claims on idle funds.
  - This also removes the separate code path for written-off vaults (ADR 0015 §2): one pull, from
    the stranded vault if written off, otherwise from the active vault.
- **Brief tests 1 to 3** through the real escrow on the fork (`test/fork/AaveStataEscrow.t.sol`):
  - round trip after 30 days, within 2 units;
  - a liquidity crunch (60k WETH supplied, USDC borrowed down to 300k) gives a partial claim with the

  - a fuzz test showing `totalAssets` never over-reports;
  - a test showing a wrapper pause does not block claims.
- **`MockYieldVault`** (`src/testnet/MockYieldVault.sol`): an OpenZeppelin ERC4626 with offset 12

  - Linear APY, capped at the USDC it holds.

  - Unit tests in `test/unit/MockYieldVault.t.sol` (7).

  - `MockYieldVaultConformanceTest`;

**Triage of the new Slither results:**

- **`_pullBestEffort` strict equality** (`pull == 0`): benign.
- **`_pullBestEffort` ignores the `withdraw` return value**: intended. The balance delta is measured
  instead, which does not trust the vault's return.
- **Reentrancy in `claim` via `_pullBestEffort`**: the call to the vault comes before the debit,
  because what is paid depends on what arrives.
  - `Escrow.claim` is `nonReentrant`, as is every function that moves tokens.
  - Only admin-approved vaults are called.
  - This ordering is unchanged from before the refactor.
- **`MockYieldVault` `owner` shadowing and a timestamp comparison**: these follow OpenZeppelin's own
  parameter names, and the timestamp result is a false positive.

## Deviations from spec

- **The brief's `MockYieldAdapter` / `AaveV3Adapter` became ERC-4626 vaults (ADR 0008).**
  - `onlyEscrow` became ERC-4626 share ownership: only the share holder can withdraw
    (`test_conformance_onlyEscrowMovesItsShares`).
  - The escrow uses `maxWithdraw` in place of `maxWithdrawable`.
- **`marketAvailableLiquidity()`** is Aave's own `Pool.getVirtualUnderlyingBalance(USDC)`, not a
  view of ours (ADR 0016). C8 reads it.
- **The mock lives in `src/testnet/`**, not `src/adapters/`: that folder is reserved for an Aave
  adapter, which D5 made unnecessary. It is a deployable contract, so it is not under `test/`.
- **The mock does not need `onlyEscrow`.** Anyone may deposit, as in any ERC-4626. Only share
  holders can exit their own shares.

## Spec concerns

- **Aave governance can upgrade the stata proxy.** This is the same trust we already place in the
  aToken. The response is `writeOffVault`, `setDefaultVault` and draining (ADR 0013).
