# C6 handoff

**Framework ADR:** [0014](../adr/0014-indexing-framework.md) (Ponder 0.17.12).
**Design ADR:** [0017](../adr/0017-indexer-design.md). It also corrects ADR 0014 on how Ponder halts.
**Notifier interface:** `services/apps/indexer/src/worker/notifier.ts`; its definition is below.

## Done

- **`services/apps/indexer` on Ponder.** It indexes the factory plus every escrow clone the factory
  creates (discovered from `EscrowCreated`). All handlers share one pure reducer
  (`src/core/reducer.ts`):
  - it mirrors `LedgerLib`/`DisputeLib` posting by posting;
  - it is idempotent on `(chainId, txHash, logIndex)`;
  - every escrow ABI event has a rule or is explicitly ignored.
- **Ledger projection.** Double-entry accounts per escrow (ADR 0017 §5):
  - guest, owner and fee claimable;
  - open principal, disputed, pending yield (dispute, guest and owner), reserve and loss debt;
  - unallocated yield, idle and deployed.

  Every event posts balanced legs. The contract's books identity holds after every event.
- **Booking projection.** Booking state, terms, freezes, disputes and all settlement figures.
- **Head awareness** (`src/worker/heads.ts`, `milestones.ts`):
  - the chain's own `latest`, `safe` and `finalized` tags, with hashes;
  - head-transition outbox `indexer_ops.head_events`, plus `NOTIFY chain_head`;
  - per-booking milestones `received`, `safe`, `finalized` and `reverted` in
    `indexer_ops.booking_milestones`, plus `NOTIFY booking_milestone`.
- **Calendar projection** (`src/worker/calendar.ts`). The escrow rows of the shared
  `calendar_blocks` table follow the brief's decided contract (ADR 0012 §3, §7), with two
  safe-direction rules added (ADR 0017 §2):
  - a cancellation frees a slot only at `safe`;
  - a deposit that reached `safe` and was then reorged out keeps its slot, and pages.
- **Invariant monitors** (`src/core/invariants.ts`, `src/worker/monitors.ts`):
  - INV-1 to INV-6 as specified;
  - RECONCILE: projection vs contract at the exact snapshot block;
  - LAG and DEEP_REORG;
  - an alert outbox `indexer_ops.alerts` (dedupe, auto-resolve) and pluggable notifiers.
- **Replay** (`src/replay/`):
  - a full rebuild into a separate schema through Ponder itself;
  - a diff up to the common block: immutable facts exact, rows compared where untouched since, and
    each schema's balances checked against its own journal;
  - a clean diff drops the schema; a difference pages (`REPLAY`).
- **Read API** (Ponder's Hono server, `src/api/index.ts`; ADR 0017 §8):
  - booking view: state, refund if cancelled now (via `@chain/shared`), accrued yield, claimable;
  - escrow summary for the owner digest, at `latest`, `safe` or `finalized`;
  - account buckets.
- **Ops:** `ops/runbook.md` (new file, indexer section) and `.env.example`.

### Notifier interface

```ts
export type Breach = {
  invariant: string;                 // "INV-1".."INV-6" | "RECONCILE" | "LAG" | "DEEP_REORG" | "REPLAY" | "CALENDAR"
  severity: "page" | "alert" | "warn";
  key: string;                       // dedupe key: one open alert per key
  escrow?: string;
  message: string;
  details?: Record<string, string | number | boolean | null>;
  response: string[];                // spec 10.4 responses, e.g. ["page","guardian_pause_deposits","halt_deployment"]
};
export type Alert = Breach & { chainId: number };
export interface Notifier { notify(alert: Alert): Promise<void>; }   // called once per newly opened alert
```

Other outboxes and channels, for C7, C8 and the agent workstream's notifier:
- **`NOTIFY chain_head`**, payload `{chainId, tag, number, hash, ts}`.
- **`NOTIFY booking_milestone`**, payload
  `{chainId, escrow, bookingId, milestone, depositBlock, depositHash}`.
- **Tables:** `indexer_ops.{head_events, booking_milestones, alerts}`.

## Deviations from spec

- **Spec 10.2, "credit claimable balances in the ledger: finalized".** The ledger credits at the
  indexed head and serves a finalized view: `summary?head=finalized` sums the journal up to the
  finalized block. The ledger is a projection, so crediting later would only hide data; the gate
  belongs to whoever acts on it.
- **Calendar rows.** Two safe-direction rules added to the "Decided" contract (ADR 0017 §2).
- **`idle`/`deployed` are book accounts, not balances** (ADR 0017 §5). The contract cannot tell
  them apart either; actual idle comes from chain reads.

## Spec concerns

- **ADR 0014 overstated Ponder's halt.** Ponder keeps retrying for up to 10 minutes after an
  unrecoverable reorg. Corrected in ADR 0017 §4 and backed by the lag monitor.
- **Ponder's `/status` is its sync head, not its indexing head.** Anything waiting on the indexer
  must use the checkpoint, as the worker does.
- **INV-3's iCal-export half needs C7's export.** C7 should add it to the same `Breach` family.

## Interfaces changed

- **No shared contract interface, event or `/v1` schema changed.**
- **`calendar_blocks`:** same DDL; C6 now writes its escrow rows (it already owned them, ADR 0012).
- **New, additive:**
  - the `indexer_ops` schema and its tables;
  - the `NOTIFY` channels;
  - the read API routes under `/v1/indexer/*`;
  - the notifier interface.

  All are documented in ADR 0017. They are C6's own interfaces, which C7, C8 and the agent
  workstream consume.
- **Test-only edits outside C6, reported per CLAUDE.md §7:**
  - `contracts/test/invariant/independent/handlers/C9Handler.sol`: `_call` is now `virtual`, so a
    C6 subclass can tape logs. No behaviour change; the C9 suites pass unchanged.
  - `contracts/foundry.toml`: a write permission for the fixture directory.
