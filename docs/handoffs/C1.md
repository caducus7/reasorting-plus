  `EscrowInit`, **every** spec 4.7 event (C2 and C3 events declared now so the ABI is stable),
  every custom error, and the full external interface.
- **`src/interfaces/IEscrowFactory.sol`**: `OwnerTerms`, events, errors and views.
- **`src/Escrow.sol`**, built from OpenZeppelin 5.6.1 parts wherever one exists (ADR 0006):
  - initialiser protected by `Initializable`; the implementation calls `_disableInitializers()`
  - EIP-712 domain `("BookingEscrow", "1", chainId, escrow)`, `bookingId = hashStruct(quote)`,
    signature checked with `SignatureChecker` (EOA or ERC-1271)
  - `deposit` / `depositWithPermit` with all 12 guards in spec order, the escrowed-value cap, and a
    balance-delta check
  - `cancelByGuest`, `cancelByProperty`, `settle`, `claim`, `freezeBooking` / `unfreezeBooking`,
    `pauseDeposits` / `unpauseDeposits`
  - settlement exactly per spec 4.4 through `SettlementLib`, with the D3 "INTENTIONAL" branch
  - lazy timelocks for fee and arbitrator; fee recipient read from the factory at settlement;
    arbitrator snapshotted (effective value) at deposit
  - `claim` per spec 4.5: pulls a shortfall from the vault bounded by `maxWithdraw`, pays partially,
    applies the `lossDebt` gates, and follows strict checks-effects-interactions
  - hooks `_accrue()` (C1: sets `lastAssets`) and `_crystalliseYield()` (C1: returns 0), plus every
    accounting field C2 and C3 need
- **`src/EscrowFactory.sol`**: OpenZeppelin `Clones` (EIP-1167), `Ownable2Step` factoryAdmin,
  onboarding approve-then-create, timelocked fee recipient, and defaults for new escrows (live
  guardian, arbitrator, vault, implementation).
- **`src/libraries/`**: `QuoteLib` (EIP-712 hashing, guard 11, spec 4.3), `SettlementLib` (spec 4.4),
  `Params` (spec 13).
- **Vault adapter:** ERC-4626 instead of a custom `IYieldAdapter`, with `address(0)` meaning no
  yield (ADR 0008). No `NullAdapter` contract is needed.
- **`script/DeployBaseSepolia.s.sol`**: refuses any chain but 84532, sanity-checks USDC on-chain, and
  reads roles from env. **Not broadcast anywhere.**
- ABIs exported to `contracts/abi/{Escrow,EscrowFactory,IEscrow,IEscrowFactory}.json`. Foundry
  artifacts land in `contracts/out/` (gitignored).
- ADRs 0005 (clones, not proxies), 0006 (toolchain pins), 0007 (defaults for review findings),
  0008 (ERC-4626 adapter).

## Deviations from spec

All of these were applied at the project owner's instruction to use my defaults; details in the ADRs.

1. Owner credits go to an address-independent `ownerClaimable` bucket, paid to the current payout
   address. Spec 4.4 credited `claimable[payoutAddress]` (ADR 0007 §1).
2. `claim()` with nothing claimable returns 0, and under `lossDebt` pays a caller's guest bucket
   even if the caller is also the payout address (ADR 0007 §1).
3. `createEscrow(payoutAddress, quoteSigner, minNightlyAtomic)` needs a prior `approveOwner` by the
   factoryAdmin. The brief had `createEscrow(owner, maxFeeBps, initialFeeBps, ...)` (ADR 0007 §2).
4. Freeze is allowed from DISPUTED; each booking has a 30-day cumulative freeze budget, then anyone
   may unfreeze (ADR 0007 §3).
5. Escrowed-value cap `maxOpenPrincipalAtomic`, checked between guards 11 and 12 (ADR 0007 §4, spec 12.3).
6. `minNightlyAtomic` must be non-zero (ADR 0007 §8).
7. Pausing uses OpenZeppelin `Pausable`: events `Paused` / `Unpaused`, error `EnforcedPause`
   (ADR 0007 §6).
8. Owner rotation via `Ownable2Step`; renounce disabled (ADR 0007 §6).
9. Yield adapter is ERC-4626, not `IYieldAdapter` (ADR 0008).
10. **Guard order (review finding 14):** the spec's order is kept, so guard 5's `lossDebt` check runs
    before `_accrue()`. CLAUDE.md rule 4 ("accrue first") holds for every other state-changing function.

## Spec concerns

- **Contract size.** `Escrow` is 19,722 bytes, leaving 4,854 bytes of headroom under EIP-170.
  C2 (accumulator, loss, reserve, deploy and redeem) plus C3 (disputes) will probably exceed it.
  Options: move settlement or disputes into an external library, lower `optimizer_runs`, or split
  disputes into a module. C2 should measure first.
- **Guest `permit` with smart wallets.** Circle's FiatTokenV2_2 has a second
  `permit(owner, spender, value, deadline, bytes signature)` that accepts ERC-1271 signatures, but
  only from *deployed* contracts. That confirms spec 4.2's reason for making the allowance path
  primary; `depositWithPermit` uses the ERC-2612 `(v, r, s)` form for EOAs.
- **Base docs error.** One Base docs page prints Base Sepolia USDC as `…3dCF7c`, which fails its own
  EIP-55 checksum. The deploy script uses the checksum-valid `0x036CbD53842c5426634e7929541eC2318f3dCF7e`
  and checks symbol and decimals on-chain before deploying.
- Spec 2 ("immutable clones") still holds; ADR 0005 records why proxies were not adopted.
